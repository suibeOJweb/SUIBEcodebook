### 编辑器 / IDE
写代码首先得有一个合适的编辑器或 IDE（集成开发环境）。总而言之，不要纠结哪个最牛逼，先挑一个能稳定写起来、社区资料多的就行。

- **VSCode**：目前最主流的免费编辑器，插件多、教程多、AI 辅助（Copilot、Cline、Continue 等）也很成熟。推荐新手首选。
- **Cursor**：基于 VSCode 改造的 AI IDE，内置对话和代码生成， vibe coding 很顺手。
- **JetBrains 系列（PyCharm、IntelliJ IDEA 等）**：功能很全的 IDE，开箱即用，但相对重一些，内存占用大。

> 小建议：先装 VSCode，等觉得自己需要更重的 IDE 或更强的 AI 再换。（主要还是学校老师基本上都用VSCode）

### 更好的ai工具
除了编辑器本身，现在也有很多专门面向编程的 AI 工具，可以帮你查错、补代码、解释概念：

- **VSCode 内置 Copilot / 各种插件**：在 VSCode 里就能免费用到 AI 辅助写代码。
- **ChatGPT / Codex**：性价比高，既能写代码也能问概念，而且Codex的token额度很实惠。
- **Claude / Claude Code**：在 coding 领域口碑很好，但国内访问麻烦（得益于它家公司过于出生的操作），一般需要中转站。
- **Cursor**：本身就是带 AI 的编辑器，开发流程很丝滑，ctrl+l，tap谁用谁知道，很爽。

### 命令行 / 终端

这个黑色窗口其实是最直接跟电脑对话的方式。常见的入口：

- **Windows**：按 `Win + R`，输入 `cmd` 或 `powershell` 回车；也可以装 Windows Terminal。
- **macOS**：打开「启动台」搜「终端」。
- **Linux**：Ctrl + Alt + T 一般是终端快捷键。

先记住几个最常用命令（不同系统可能略有差别）：

```bash
pwd          # 显示当前所在目录
ls           # 列出当前目录下的文件（Windows 用 dir）
cd 文件夹名   # 进入某个目录
cd ..        # 返回上一级目录
mkdir 文件夹名 # 创建文件夹
```

> 命令多用几次就熟了。遇到不会输的命令，直接问 AI，它会告诉你具体打什么。

### 环境变量

环境变量就是操作系统保存的一些「全局设置」，最常见的是 `PATH`。简单来说，`PATH` 告诉系统：「当我输入一个命令时，去哪些文件夹里找这个程序」。

比如你装了 Python 却提示「不是内部或外部命令」，大概率就是 `PATH` 里没加上 Python 的安装路径。

**查看与临时设置：**

```bash
echo $PATH          # macOS / Linux 查看 PATH
echo %PATH%         # Windows 查看 PATH
export PATH=$PATH:/usr/local/bin  # 临时添加（macOS / Linux）
```

**永久设置：**

- **Windows**：「此电脑」右键 → 属性 → 高级系统设置 → 环境变量 → 编辑 `Path` → 添加新路径。
- **macOS / Linux**：修改终端配置文件，常见如 `~/.zshrc` 或 `~/.bashrc`，加一行：
  ```bash
  export PATH=$PATH:/你的/程序/路径
  ```
  然后执行 `source ~/.zshrc` 让它生效。

> 遇到「命令找不到」的报错，第一反应就是检查环境变量，第二反应就是问 AI。

### git
除了以上ai工具之外，你还需要一些关于如何管理代码库的知识，以下是常见命令操作：

```bash
git push # 默认行为推送代码
git pull # 默认行为拉取代码
git push origin frontend # 往远程前端分支推送代码
git stash # 暂存现有更改/暂存更改但未被推送的代码
git stash pop # 弹出暂存代码
git merge frontend # 归并frontend分支到当前分支
git checkout backend # 切换到backend分支
git checkout -b backend # 创建并切换到backend分支
# 注意：checkout强行执行会丢失更改的代码
git fetch --all # 拉取所有远程分支信息
# 软回退：保留工作区和暂存区的修改
git reset --soft <commit-id>
# 混合回退（默认）：保留工作区修改，清空暂存区
git reset --mixed <commit-id>
# 硬回退：完全回退，丢弃所有修改（危险⚠️）
git reset --hard <commit-id>
```

### GitHub / 代码托管平台

Git 是本地管理代码的工具，而 **GitHub** 是把这些代码放到网上的平台，方便备份、协作和展示。类似的平台还有 [Gitee](https://gitee.com/)（国内访问快）、[GitLab](https://gitlab.com/) 等。

新生可以先注册一个 GitHub 账号，这是程序员的「名片」之一。

常用操作：

```bash
git clone https://github.com/用户名/仓库名.git  # 把别人的项目下载到本地
git remote add origin git@github.com:用户名/仓库名.git  # 关联远程仓库
git push -u origin main  # 第一次推送本地代码到远程
```

几个概念：

- **仓库（Repository）**：一个项目对应一个仓库，代码都放在里面。
- **README.md**：仓库首页的说明文件，用 markdown 写。
- **.gitignore**：告诉 Git 哪些文件不要提交，比如临时文件、依赖目录。
- **Fork / PR**：复制别人的项目并贡献代码，后续学开源会用到。

> 如果 GitHub 访问不稳定，可以先用 Gitee 练习，等学会科学上网再迁移到 GitHub。

### ssh

SSH 是一种远程登录和身份验证协议。说人话：它让你能安全地连接到远程服务器，或者让 Git 用密钥而不是密码访问 GitHub。

最常见的场景有两个：

1. **连接远程服务器**：比如买了一台云服务器，想从本地电脑操作它。
   ```bash
   ssh 用户名@服务器地址
   ```
2. **免密访问 GitHub**：用 HTTPS 推代码每次都要输密码，用 SSH 密钥就可以一劳永逸。

**生成 SSH 密钥：**

```bash
ssh-keygen -t ed25519 -C "你的邮箱@example.com"
```

然后按提示回车，默认会在 `~/.ssh/` 下生成 `id_ed25519`（私钥）和 `id_ed25519.pub`（公钥）。

**添加到 GitHub：**

1. 打开 `~/.ssh/id_ed25519.pub`，复制里面的内容。
2. 进入 GitHub → Settings → SSH and GPG keys → New SSH key → 粘贴保存。
3. 测试是否成功：
   ```bash
   ssh -T git@github.com
   ```

> 私钥（没有 `.pub` 的那个）千万不要泄露给别人，相当于你的家门钥匙。
